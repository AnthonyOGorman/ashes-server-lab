# Windows C++ build

To start the game and local services, double-click `Start C++ Client.cmd` in the workspace root. It starts the built backend when needed and launches the game with the local tether connection. You can also use **Start client & connect** at http://127.0.0.1:8865/. Select **Ashes C++ Lab**, choose your character, and press **Play** in the game. A second launch request reuses the client already launched by this lab; another independently launched game must be closed first.

The launcher keeps a separate profile in `CPP/client-profile` and session logs in `CPP/runs/<session>/`. The dashboard reports local login and world connection only when observed in the launched client's log. Successful lobby connection does not establish that gameplay initialization is complete.

The game uses the interactive Windows desktop `winsta0\default` with a normal visible startup window, independently of the hidden backend. Its display arguments are `-windowed -ResX=1280 -ResY=720 -WinX=100 -WinY=100 -ForceRes`. The tether port comes from the C++ configuration. The game's log records the actual parsed command line for troubleshooting.

Run from the workspace root:

```powershell
.\CPP\tools\Build-CPP.ps1
.\CPP\tools\Build-CPP.ps1 -Configuration Release
```

The script finds Visual Studio 2022's C++ tools, runs its bundled CMake, and executes the core parity, movement compatibility and offline terrain suites. The movement suite uses synthetic packed containers and offline simulation cases; it does not certify real-client movement. It uses the `windows-msvc` preset and keeps output in `CPP/build/msvc`. Stop only the isolated C++ lab before rebuilding a running executable.

The installed MinGW compiler fails at startup with a missing `crc32_combine` entry point and `MSVCR90.dll`. These are compiler runtime failures. The C++ project now builds with MSVC; no compiler reinstall or downloaded replacement DLL is required for this project. The locally supplied nghttp2, SQLite, and OpenSSL C runtime DLLs remain dependencies, with generated MSVC import libraries.

Prerequisites: Visual Studio 2022 with Desktop development with C++, its CMake component, and the local dependency DLLs in `C:/msys64/mingw64/bin`. Dependency headers are vendored. The input adapter build tag is generated by CMake from its source and protocol hashes.

Launch the isolated backend from the workspace root:

```powershell
.\CPP\build\msvc\Debug\ashes_lab.exe --root "$PWD\CPP" --start-services
```

Open http://127.0.0.1:8865. The C++ configuration uses lobby 16051, world 18089, and tether 18090. The original Python lab uses separate ports.

Passing native and offline integration checks does not verify the full real-client initialization and movement flow. That verification is still pending.
